## Booking Tickets Abroad

There's one thing you always need to do before a trip: make the bookings you need. Think of the Ghibli Park in Japan or train tickets in Spain. Or the other way around: sometimes you're abroad and want to watch a Korean streaming service. But quite often, you can't use the service.

![Ghibli](/assets/img/content/AWS/004/001.webp)

`> The Ghibli Museum has to be booked two months ahead.`{:.img-caption}

That's because the service's servers check your IP, spot a public IP coming from abroad rather than from their own country, and block it. So to get around that, we reach for VPN apps that make our traffic look like it comes from a US or Japanese IP.

## VPNs (Virtual Private Networks) and Dedicated Lines

### Dedicated lines

First, dedicated lines. As the name says, a dedicated line physically connects one end directly to the other. AWS has services like this too, such as Direct Connect.

### VPN (Virtual Private Network)

A [VPN (Virtual Private Network)](https://docs.aws.amazon.com/vpn/latest/s2svpn/Examples.html#SingleVPN){:target='_blank'}, on the other hand, is a tunneling technology that uses the public network but creates a virtual passage that behaves like a direct connection. On top of that, it provides additional security protocols (IPsec, SSL).

![AWS VPN](/assets/img/content/AWS/004/002.webp)

`> A single Site-to-Site VPN connection`{:.img-caption}

## Proxy

Instead of a VPN, here we'll build a simple proxy server with AWS EC2 and use it to get around IP blocks. So what exactly is a proxy?

> proxy
> - the authority to act for another
> - a person who acts for another

True to the word, a proxy acts as a middleman in network communication. It relays requests and responses between the client and the server. The client sends its request to the proxy, and the proxy passes the request on to the server.

<pre class="mermaid center">
architecture-beta
    service server(custom:chrome)[Browser]

    service server3(custom:server)[Proxy]

    service server4(custom:internet)[Ticket Server]

    server:R -- L:server3
    server3:R -- L:server4
</pre>

### Use a proxy you can trust

Search the internet for proxies and you'll find all sorts of proxy servers. But whether a given proxy server can be trusted is your own responsibility, so be careful when you use one. Here we'll use AWS EC2 to **build a safe proxy that only you can use.**

### Types of proxies

- Forward proxy: used on the client side
- Reverse proxy: used on the server side

NGINX, which receives requests in front of a server and passes them on to it, is the classic reverse proxy. The proxy we're building is a forward proxy that works on the client side.

## Two Ways to Set Up the Proxy

We'll use EC2 as a proxy in two ways:

- An SSH tunneling proxy
- Using GOST (Go Simple Tunnel)

## SSH Tunneling Proxy

Let's turn EC2 into a proxy using SSH tunneling. This works as shown in *Figure 1.* below.

1. Create an SSH tunnel between your local computer and EC2
2. Point the browser's proxy setting at the SSH tunnel

The browser's requests go through the SSH tunnel, the actual traffic goes out and comes back through EC2, and the response is handed back to the browser.

<pre class="mermaid center">
architecture-beta
    group client(custom:computer)[Local Computer]
        service server(custom:chrome)[Browser] in client
        service server2(custom:tunnel)[SSH Tunnel] in client

    service server3(aws:ec2)[EC2]

    service server4(custom:internet)[Ticket Server]

    server:R -- L:server2
    server2:R -- L:server3
    server3:R -- L:server4
</pre>
`> Figure 1. SSH tunneling proxy`{:.img-caption}

### EC2 settings

We'll set up an EC2 instance in a public subnet with an internet gateway attached, using the following settings:

- Region: Tokyo ap-northeast-1
- AWS EC2
  - Amazon Linux 2023
  - Set a key pair
  - Auto-assign public IP: enabled
  - Add a security group (SG) inbound rule: My IP / port 22

Here we'll create the tunnel with [MobaXterm](https://mobaxterm.mobatek.net/download.html){:target='_blank'}. Select the `Tunneling` menu at the top.

### New SSH tunnel

In the MobaSSHTunnel window, click the `New SSH tunnel` button at the bottom to create a tunnel.
At the top, select `Dynamic port forwarding (SOCKS proxy)` and enter the following:

1. `Forwarded port` : enter 8080
2. Enter the SSH server (EC2) details

Let's start the tunnel we made. A tunnel is now set up between your local computer and the EC2 instance you'll use as a proxy. Anything that uses port 8080 on your local computer has its traffic delivered to EC2 through the SSH tunnel.

Now we need to set up a web proxy on port 8080 so Chrome can use the SSH tunnel we created. For the web proxy, we'll use the [Proxy SwitchyOmega](https://chromewebstore.google.com/detail/proxy-switchyomega/padekgcemlokbadohgkifijomclgjgif){:target='_blank'} extension.

![New SSH tunnel](/assets/img/content/AWS/004/005.webp){:.img-m}

### Check the new IP

Chrome now uses EC2 as its proxy server through the SSH tunnel. Let's check the new IP. You can see your public IP with the command below. Or just search for "what is my IP" in your browser and check that it matches the IP of the EC2 instance acting as the proxy!

```bash
$ curl -x http://localhost:8080 https://ifconfig.me
```

## SOCKS5

When we set up the proxy above, we chose a type called `SOCK5`. What is it?

`SOCKS5` is a general-purpose proxy protocol that is independent of application-layer protocols. So it supports many protocols, including HTTP, HTTPS, FTP and SMTP.

### SOCKS5 characteristics

- Supports TCP and UDP
- Passes the application's original request through without modifying it
- Doesn't encrypt traffic; it needs to be used together with SSH tunneling
- Not every application supports SOCKS5, so check compatibility before using it

A SOCKS5 proxy handles HTTP and HTTPS traffic well in most cases, but for some use cases an HTTP-only proxy may be a better fit. Choose the proxy protocol based on your situation.

## Proxies at Work

So far we've used EC2 as a proxy in two ways. We could stop here, but proxies do come up in real work, so let's look a bit further at proxy settings.

### When are they used?

Proxies at work show up in quite specific situations: namely, when you have to set up a proxy server in an air-gapped (closed) network. For example, when third-party products are used in a closed network, their traffic is managed through a proxy.

In a closed network, a proxy can consolidate all connection points to the outside into one. With only a single point to manage, network security and operational efficiency improve a lot.

### Checking the traffic

In the exercises so far, the browser's web proxy sent only web traffic to EC2. With the proxy set up, test with the command below and you'll see that traffic from anything other than the browser doesn't go through the proxy.

```bash
$ curl https://ifconfig.me
```

### Sending all traffic through the proxy

If all traffic in a closed network has to go through the proxy, this won't do, right? So this time let's change the OS settings so that all traffic from the local computer goes to the proxy.

## Proxy Settings on Windows

On Windows, search for "Change proxy settings" (manual proxy setup). Turning on a manual proxy is an easy way to send all traffic to the proxy.

![Manual proxy](/assets/img/content/AWS/004/008.webp){:.img-m}

## Proxy Settings on Linux

### Temporary settings

You can register temporary environment variables with the export command. *all_proxy* is the environment variable for a `SOCKS5` proxy. You can also register environment variables per protocol, such as http / https.

```bash
$ export all_proxy=socks5://127.0.0.1:8080
```

```bash
$ export http_proxy=http://127.0.0.1:8080
$ export https_proxy=https://127.0.0.1:8080
$ export ftp_proxy=ftp://127.0.0.1:8080
$ export no_proxy="localhost,127.0.0.1,::1"
```

Some applications use uppercase variables, so it's a good idea to set the uppercase ones too.

```bash
$ export ALL_PROXY=$all_proxy
```

You can confirm that traffic goes through the proxy with the `curl` command below.

```bash
$ curl -v google.com
```

To turn the proxy off, restart the shell or clear the environment variable with the `unset` command.

```bash
$ unset all_proxy
```

### Permanent settings

You can make the proxy permanent by editing the environment file.

```bash
$ sudo vim /etc/environment
```

<div class="file-name">/etc/environment</div>

```text
all_proxy=socks5://127.0.0.1:8080
ALL_PROXY=$all_proxy
```

Reconnect to the shell, or restart it with the command below, so the new environment variables take effect.

```bash
source ~/.bashrc
```

## Wrapping Up

A proxy is a server that acts as a 'middleman' between the client and the server. Proxy servers can be very useful depending on the situation, but since they can change your IP, they can also be used for malicious purposes. Always use them with care.

We tried setting just a web proxy, and switching the whole OS's traffic to a proxy with environment variables. As a more modern way to configure proxies, `NetworkManager` would be worth studying.
