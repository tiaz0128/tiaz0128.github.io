## How DNS Works

DNS (Domain Name System) is the system that turns domain names people can easily remember (e.g. google.com) into IP addresses computers can recognize (e.g. 172.217.31.174). Here's how a DNS query is processed.

### The DNS Query Process

1. When the user enters a domain name in the browser, the operating system first checks its local cache.
2. If the local cache doesn't have it, the OS sends a query to the configured local DNS server (usually provided by the ISP).
3. The local DNS server checks its own cache, and if the answer isn't there, starts by querying a Root DNS server.
4. The Root DNS points to the appropriate TLD server (e.g. .com, .net, .kr).
5. The TLD server provides the Authoritative DNS server information for the domain.
6. The Authoritative DNS server finally returns the IP address for the domain.
7. This information is cached on the local DNS server, and the user connects to the website using the IP address received.

![How a DNS query works](/assets/img/content/Network/004/001.webp)

`> How a DNS query works`{:.img-caption}

In this process, DNS uses two kinds of queries, recursive and iterative, and asks hierarchically: starting from the Root DNS, through the TLD (Top-Level Domain), and finally to the Authoritative DNS server.

## Recursive Query

> It's like asking a server at a restaurant, "Where's my pizza?" and the server goes to the kitchen, finds the pizza and brings it to you.

![Recursive Query](/assets/img/content/Network/004/006.webp){:.img-m}

`> Recursive Query`{:.img-caption}

When a host asks the DNS server "What's the IP of google.com?", the DNS server goes around to all the other name servers itself, finds the final IP address and tells you.

**The DNS server does all the work for you, and you get a complete answer with a single request.**

## Iterative Query

> It's like asking a server at a restaurant, "Where's my pizza?" and the server only says "It's probably in the kitchen," so you have to go to the kitchen yourself and ask again.

![Iterative Query](/assets/img/content/Network/004/007.webp){:.img-m}

`> Iterative Query`{:.img-caption}

When you ask a DNS server, all you get back is "Go ask this server." Ask that server and you're pointed to yet another one... and so on, so you have to visit several servers yourself.

**The client has to ask several servers directly, getting the information step by step over multiple requests.**

## How Each Query Is Used in Practice

In short, the difference is in the request: a recursive query says "Please do everything for me," while an iterative query says "Just tell me where to go next."

Regular users' computers mostly use recursive queries, because they're convenient. **DNS servers, on the other hand, mostly use iterative queries among themselves, to spread out the server load**{:.orange}.

## The hosts File: Hands-On with Local DNS

Let's see and learn the DNS concepts through hands-on practice. We'll use Docker on Linux/Mac. If you're on Windows, try it with WSL!

### Nginx Web Server

First, let's run an Nginx web server as a Docker container.

```bash
$ docker run -d --rm -p 8080:80 --name my-website nginx
```

### Setting Up a Local DNS Environment

To test DNS behavior locally, let's edit the `/etc/hosts` file. By editing `/etc/hosts`, you can map a specific domain directly to an IP of your choice.

```bash
$ sudo vim /etc/hosts
```

<div class="file-name">/etc/hosts</div>
```text
127.0.0.1 my-website
```

On Windows, open the file at the path below in PowerShell with administrator rights and edit it.

```bash
> notepad C:\\Windows\\System32\\drivers\\etc\\hosts
```

<div class="file-name">C:\Windows\System32\drivers\etc\hosts</div>
```text
127.0.0.1 my-website
```

### Check in the Browser

Let's try connecting with the domain name `my-website`. As the operating system checks its local DNS cache, it reads the hosts file we edited, and you can see that it connects to the NGINX server.

```text
http://my-website:8080
```

## Wireshark : Hands-On with DNS Queries

Let's take a closer look at how DNS works by **practicing DNS lookups with Wireshark**{:.orange}.

### Wireshark

![Wireshark logo](/assets/img/content/Network/004/004.webp){:.img-m}

Wireshark is an open-source network packet analyzer, a powerful tool for capturing network traffic and analyzing it in real time. It supports a wide range of protocols and is widely used for troubleshooting networks, security analysis and understanding how protocols behave.

### Installing Wireshark

Follow the [Download Wireshark](https://www.wireshark.org/download.html){:target="_blank"} page and install the right version for your operating system.

### Wireshark Filtering

Pick the NIC (Network Interface Card) to capture on. In my case, I chose `WI-FI`. Then, to watch only DNS packets, set the Wireshark filter as follows.

```text
udp.port==53
```

![Wireshark filtering](/assets/img/content/Network/004/003.webp)

`> Filtering on UDP port 53 to watch DNS`{:.img-caption}

### dig +trace

The `dig +trace` command shows the entire DNS lookup process. Because the lookup runs from the very beginning, you can see the packets for the whole DNS query in Wireshark.

```bash
$ dig +trace google.com
```

1. Query a root DNS server
2. Query the .com TLD server
3. Query google.com's authoritative name server
4. Finally obtain google.com's IP address

I recommend copying the packets and handing them to an AI to analyze them one by one.

![Wireshark screen](/assets/img/content/Network/004/005.webp){:.img-m}

`> Copy the DNS packets and get some help from AI!`{:.img-caption}

## Wrapping Up

In this post, we went from the basic concepts of DNS and how it works to seeing it in action in a real environment through hands-on practice.

- Lookups go hierarchically, starting from the local DNS cache, through the Root and TLD, to the Authoritative DNS server
- DNS queries are either recursive or iterative
- You can add local DNS entries through the hosts file
- We analyzed real DNS query packets with Wireshark and `dig +trace`
