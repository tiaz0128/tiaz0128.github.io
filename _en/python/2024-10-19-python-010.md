Software often has to handle several tasks at the same time. To do that, it's important to understand the concepts of programs, processes, and threads.

## Program

Generally, a program is a set of instructions stored in a static state on a disk such as a hard disk drive (HDD) or SSD. By 'static state,' I mean code that isn't running.

### IPC (Inter-Process Communication)

Because processes run independently, the various ways they communicate with each other are called IPC (Inter-Process Communication). Methods include pipes, sockets, shared memory, and message queues. This communication can introduce some overhead.

### PCB (Process Control Block)

A data structure called the PCB (Process Control Block) is created for each process. The PCB stores various information about the process.

- Process ID
- Process state
- Program counter
- CPU registers, etc.

Based on this information, each process is allocated system resources such as CPU time and memory.

## Thread

A process is the state in which a program has been given memory and can execute instructions. So who actually executes the instructions in a process? That's the job of a thread.

A thread is a small unit of execution that runs inside a process. As the word suggests, you can think of it as a "thread of execution" or a "flow of control." Every process contains at least one thread.

A single CPU core can execute only one thread at any given moment. So even when several threads seem to run at the same time, they're actually taking turns very quickly.

### Context Switching

Context switching means pausing the currently running process/thread and running a different one. Each time, the previous state (the context) is saved and the switch to the new state is made.

![Performance](/assets/img/content/python/010/001.webp){:.img-s}

Does adding more threads make things faster? Maybe, maybe not. Context switching is itself a piece of work, so if it happens too often, it becomes overhead. That's why striking the right balance matters.

### The threading Module

In Python, you can create threads with the Thread class in the built-in threading module. You start a thread with the `start` method.

- `target` : The function the thread will run
- `args` : Arguments passed as an iterable
- `kwargs` : Arguments passed as a dict

```python
import threading

thread = threading.Thread(target=lambda x: print(f"Hello, {x}"), args=("Thread",))

thread.start()
```

```text
Hello, Thread
```

### Subclassing threading.Thread

You can define a thread class by subclassing Thread. Instead of using the `target` argument, you override the `run` method to define the work the thread will do.

```python
import threading

class MyThread(threading.Thread):
    def __init__(self, name: str):
        super().__init__()        
        self.name = name
        
    def run(self):
        print(f"Hello, {self.name}")

if __name__ == "__main__":
    thread = MyThread("MyThread")
    thread.start()
```

### Current Thread Information

You can check information about the current thread with the `current_thread` method.

- `ident` : The thread's unique identifier
- `name` :
  - By default, shown as "Thread-number (function name)"
  - For the main thread = MainThread

```python
import threading as th

def sub_thread():
    print(f"{th.current_thread().name} : {th.current_thread().ident}")

thread1 = th.Thread(target=sub_thread)
thread2 = th.Thread(target=sub_thread)

if __name__ == "__main__":
    thread1.start()
    thread2.start()

    print(f"{th.current_thread().name} Done")
```

```text
Thread-1 (sub_thread) : 139696827188800
Thread-2 (sub_thread) : 140045886248512
MainThread Done
```

## Thread Concurrency

Threads have the property of concurrency: they take turns running. They don't actually run at the same time; the CPU switches between threads so quickly that it looks that way.

If you run the code below, the order in which the main thread and the sub thread run may differ each time, and that's determined by the operating system's scheduler.

```python
import threading as th

def print_numbers(i: int):
    for j in range(1, i + 1):
        print(f"Sub Thread : {j}")

thread1 = th.Thread(target=print_numbers, args=(100,))

if __name__ == "__main__":
    thread1.start()
    print("MainThread Done")
```

```text
Sub Thread : 6
Sub Thread : 7
...
MainThread Done
...
Sub Thread: 100
```

## The join Method

Let's look at the `join` method, which makes a thread wait until another thread finishes. It's handy for controlling the order of work or handling tasks that depend on each other.

```python
import threading as th

def print_numbers(i: int):
    for j in range(1, i + 1):
        print(f"Sub Thread : {j}")

sub_thread = th.Thread(target=print_numbers, args=(100,))

if __name__ == "__main__":
    sub_thread.start()
    sub_thread.join()

    print("MainThread Done")
```

With the `join` method, you can see that the main thread (MainThread) waits until the sub thread (Sub Thread) finishes its work, and only then prints the Done message.  

```text
...
Sub Thread : 99
Sub Thread : 100
MainThread Done
```

If you want to run several threads one after another, you can do it like this. You'll see that thread2 starts its work only after thread1 has completely finished.

```python
if __name__ == "__main__":
    thread1.start()
    thread1.join()

    thread2.start()
    thread2.join()
    print("MainThread Done")
```

## Daemon Threads

A daemon thread is a background thread that ends when the main thread ends. It's mainly used for work that supports the main thread. You create one by setting the `daemon` argument on a regular thread.

```python
daemon_thread = th.Thread(target=background_task, daemon=True)
```

```python
import threading as th
import time

def background_task():
    while True:
        print("Daemon thread is running...")
        time.sleep(1)

daemon_thread = th.Thread(target=background_task, daemon=True)

if __name__ == "__main__":
    daemon_thread.start()
    print("Main thread is running...")
    time.sleep(3)
    print("Main thread is ending...")
```

```text
Main thread is running...
Daemon thread is running...
Daemon thread is running...
Daemon thread is running...
Main thread is ending...
Daemon thread is running...
```

## The is_alive Method

You can use the `is_alive` method to check whether a thread is currently running. It's useful for one thread to monitor what another thread is doing, and especially handy for debugging and logging.

### Example: Monitoring

```python
import threading as th
import time

def monitor_thread(thread_to_monitor: th.Thread):
    while thread_to_monitor.is_alive():
        print(f"Monitoring: {thread_to_monitor.name} is running")
        time.sleep(0.5)
    print(f"Monitoring: {thread_to_monitor.name} has finished")

def worker():
    print(f"{th.current_thread().name} started")
    time.sleep(1)
    print(f"{th.current_thread().name} finished")

if __name__ == "__main__":
    work_thread = th.Thread(target=worker, name="WorkerThread")

    monitor = th.Thread(
        target=monitor_thread, args=(work_thread,), name="MonitorThread", daemon=True
    )

    work_thread.start()
    monitor.start()

    work_thread.join()
```

1. Create work_thread first and pass it to the monitor thread.
2. The monitor checks whether work_thread is running with `is_alive()`.
3. When work_thread finishes, the main thread (MainThread) ends, and so does monitor, since it's a daemon thread.

```text
WorkerThread started
Monitoring: WorkerThread is running
Monitoring: WorkerThread is running
WorkerThread finished
Monitoring: WorkerThread has finished
```
