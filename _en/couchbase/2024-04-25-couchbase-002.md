## Prologue

At work, I built logic that stores JSON data as key-value pairs in AWS DynamoDB. Once it was actually running in production, a few problems showed up that we hadn't anticipated during development.

1. Cost
2. Item size limit
3. Difficulty developing the standalone edition

![Pinocchio meme](/assets/img/content/Couchbase/002/006.webp){:.img-s}

`> DynamoDB is more expensive than you think`{:.img-caption}

## What Running DynamoDB Taught Us

### 1. Cost

**The biggest problem, first of all, was cost.**{:.yellow} To keep tenants separate, we ran a DynamoDB for every user, and that got very expensive.

### 2. Item Size Limit

Because [the maximum size of a single item is limited to 400KB](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/ServiceQuotas.html#limits-data-types){:target="_blank"}, we had trouble storing JSON data that couldn't be split any further.

### 3. Difficulty Developing the Standalone Edition

Besides the SaaS service, the company also offered an installable standalone edition. Of course, `amazon/dynamodb-local` was an option. But we had already decided to drop DynamoDB from the SaaS because of cost, and using DynamoDB for the standalone edition would most likely have been a bad choice for maintenance down the road.

## An AWS Architecture Using Couchbase

The key to the architecture for removing DynamoDB was to keep the JSON data in S3 and work with it from there. To do that, we adopted the `Analytics Links` feature.

![Architecture](/assets/img/content/Couchbase/002/005.webp){:.img-m}
`> Analytics Links - s3`{:.img-caption}

## Analytics Links

Let's try Couchbase Analytics Links, following the [Managing Links](https://docs.couchbase.com/server/current/analytics/manage-links.html){:target="_blank"} page.

First, you can create and manage links from the `Analytics` tab in the left sidebar. When you create a link, you'll see its label shown. The external links to public clouds stand out in particular, and here we'll create a link to `S3`.

- `AZUREBLOB` : Microsoft Azure Blob storage
- `GCS` : Google Cloud Storage
- `S3` : Amazon S3 service

![Types of Analytics Links](/assets/img/content/Couchbase/002/001.webp){:.img-s}

### Creating an S3 Link

To create a link you need an `Access Key ID`, a `Secret Access Key` and a `Region`. If needed, also enter the `Session Token` for [temporary credentials](/AWS/1){:target="_blank"}.

![Creating an S3 link](/assets/img/content/Couchbase/002/002.webp){:.img-s}

### Creating a Collection

Now create a collection using the S3 bucket name and path. You can also create it for a specific file format and file name.

![Creating an Analytics Links collection](/assets/img/content/Couchbase/002/003.webp){:.img-s}

### Uploading Files to S3

Using the code below, I saved the airline collection data as individual files and uploaded them to the bucket above.

```python
inventory_scope = self.bucket.scope("inventory")

sql_query = "SELECT RAW airline FROM airline"

row_iter = inventory_scope.query(
    sql_query,
    QueryOptions(positional_parameters=["airline"]),
)

for row in row_iter:
    key = row["type"] + str(row["id"])
    with open(f"{key}.json", "w") as fp:
        logging.info(row)
        json.dump(row, fp)
```

### SQL++

Once the collection is created correctly, you can pull data from that bucket. The data in the fetched documents can be processed with SQL++.

```sql
SELECT country
     , count(country) as cnt
FROM airline
WHERE country IS NOT NULL
GROUP 
   BY country
```

## Analytics Links: Developing with the SDK

Let's do the same work we did in the Web Console, this time as `python` logic using the SDK.

### Creating a Collection

In SQL++, an Analytics Links collection is called a `DATASET`. Just as we wrote a _create_ query before, you can create a DATASET by running a query through the `analytics_query` method.

```python
query = """
    CREATE EXTERNAL DATASET IF NOT EXISTS `tiaz0128`.`airline`
        ON `tiaz0128-couchbase-link` 
        AT `Default`.`tiaz0128` 
    USING "airline/"
    WITH {"format": "json", "include": "*.json"};
"""

result = cluster.analytics_query(query)
list(result)
result.metadata().status == "success"
```

### Querying Data: SQL++

Likewise, you can run SQL++ queries with the `analytics_query` method.

```python
query = """
    SELECT country
         , count(country) as cnt
      FROM airline
     WHERE country IS NOT NULL
     GROUP 
        BY country
"""

result = self.cluster.analytics_query(query)
for row in result:
    print(row)
```

```text
{"count": 21,"country": "France"}
{"count": 39,"country": "United Kingdom"}
{"count": 127,"country": "United States"}
```

## Epilogue

We used DynamoDB in production to store JSON data, but ran into a number of problems. The solution came down to two things:

- Keep the actual JSON data in S3
- Query the data through Analytics Links

Keeping the actual JSON data in AWS S3 and using SQL++ through Analytics Links to fetch it seems like a good approach. 😊
