Let's install Linux on Windows using WSL and set up a development environment.

## Most of Us Are on Windows

Most PCs run Windows. I develop on Windows too, both at work and at home. And I'm not alone: plenty of developers work on Windows.

## "Real Developers Use a MacBook!"

Most of you have heard this at least once, and lots of people agree with it. So why does everyone say so? Here's what I found inconvenient about developing on Windows.

1. Some libraries aren't supported on Windows or simply don't work there
2. The real servers you deploy to after development almost always run Linux

The biggest pain was that **I had no choice but to develop and test in an environment different from the server**{:.orange} where the code actually runs after deployment.

## An Alternative: Developing in the Cloud

The alternative I first considered was a service like AWS EC2. Connecting VS Code to EC2 and developing there was perfectly doable. But that had its own problem: **the performance of EC2 itself.**

![EC2 free tier](/assets/img/content/tool/001/001.webp){:.img-l}

`> The specs of the AWS EC2 free tier`{:.img-caption}

A free-tier EC2 instance has 1 CPU and 1GB of memory. If you actually connect VS Code and develop on it, CPU usage spikes and the EC2 instance frequently freezes up. Of course a more powerful EC2 instance would be nice, but **you can't ignore the cost either.**

## Installing Linux on Windows

The computers most of us use today are far more powerful than a free-tier EC2 instance. I'm still happily developing on a computer that's over five years old. So why not just install Linux on our own machines?

There are roughly three ways to set up a Linux environment on Windows.

1. Install Linux with dual booting
2. Install Linux in a virtual machine
3. **Use WSL**{:.orange}

Of these options, we'll build our development environment with WSL, the easiest and most convenient one. Here, **we'll set up an** `Ubuntu` **environment.**

## WSL Environment Overview

[WSL comes in two versions, 1 and 2.](https://learn.microsoft.com/en-us/windows/wsl/compare-versions?source=recommendations){:target="_blank"} In this post, we'll install Ubuntu with WSL2, connect to it from VS Code and run a simple Python Flask app, which fetches data from MariaDB installed on Windows.

## Enabling WSL and Installing Ubuntu

On Windows 10 version 2004 or later (build 19041 or later) or Windows 11, run PowerShell as administrator. First, use the command below to enable the WSL feature, which **also automatically installs a default Linux distribution.**

<div class="file-name">Powershell</div>

```bash
> wsl --install
```

The `wsl --install` command automatically installs WSL and a default Linux distribution. In most cases, Ubuntu is installed by default. After installation, the installed distribution starts automatically.

Once it's installed, enter a username and password. This account is treated as the Linux administrator, which can run sudo (superuser) administrative commands. I'll use `ubuntu` as both the username and password.

<div class="file-name">Powershell</div>

```bash
Enter new UNIX username: ubuntu
Enter new UNIX password: ubuntu
Retype new UNIX password: ubuntu
passwd: password updated successfully
Installation successful!
```

At this point, you'll see the shell has switched over to the Ubuntu environment. You can leave the Ubuntu environment by closing the window or with the `exit` command.

```bash
ubuntu@DESKTOP-FR5BQJB:~$
```

## Changing the Default WSL Distribution

Back in PowerShell, let's look at a few more commands.

The `wsl -l -v` command lists the distributions you can run with WSL. The one marked with `*` is what starts when you run WSL. `STATE` shows whether it's currently running, and a `VERSION` of 2 means WSL2. Incidentally, you can see that Docker Desktop also runs on WSL2.

<div class="file-name">Powershell</div>

```bash
> wsl -l -v
```

```bash
  NAME                   STATE           VERSION
* Ubuntu                 Running         2
  docker-desktop-data    Running         2
  docker-desktop         Running         2
```

If Docker Desktop is installed and docker is set as the default, you'll need to change it. Specify the target's `NAME` in the command below to switch.

<div class="file-name">Powershell</div>

```bash
> wsl -s {NAME}

> wsl -s Ubuntu
```

## Installing & Removing a Specific Distribution

To install a specific Linux distribution, you can name it explicitly. First, check the list of available distributions with `wsl -l --online`.

<div class="file-name">Powershell</div>

```bash
> wsl -l --online
```

```bash
NAME                                   FRIENDLY NAME
Ubuntu                                 Ubuntu
Debian                                 Debian GNU/Linux
kali-linux                             Kali Linux Rolling
Ubuntu-18.04                           Ubuntu 18.04 LTS
```

Install one of the available distributions by its `NAME` with the command below.

<div class="file-name">Powershell</div>

```bash
> wsl --install -d Debian
```

To remove one, pass the distribution's `NAME` to the following command. It unregisters it from WSL and deletes all of that distribution's data. If you install it again with `wsl --install {NAME}`, you get the distribution with fresh data.

If you want to remove the distribution's installation package completely as well, uninstall it from your installed apps. That removes both the distribution's package and all of its data from your system.

<div class="file-name">Powershell</div>
```bash
> wsl --unregister Debian
```

## Connecting to the Host's MariaDB from WSL

Since WSL is a virtual machine, localhost points to the WSL instance. From WSL, Windows is referred to as the `Host`.

Let's connect from WSL to the MariaDB installed on the Host. To do that, we need to find and use the Host's actual IP address. You can find the Windows Host address from WSL with the following command.

<div class="file-name">Ubuntu</div>

```bash
$ ip route show | grep -i default | awk '{ print $3}'

172.25.16.1
```

Here's how to find WSL's own IP address. Look for the `inet` line in the output; it contains the WSL2 IP address. `172.25.18.88` is the WSL IP address.

<div class="file-name">Ubuntu</div>

```bash
$ ip addr show eth0
```

```text
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc mq state UP group
    link/ether 00:15:5d:68:e3:09 brd ff:ff:ff:ff:ff:ff
    inet 172.25.18.88/20 brd 172.25.31.255 scope global eth0
       valid_lft forever preferred_lft forever
    inet6 fe80::215:5dff:fe68:e309/64 scope link 
       valid_lft forever preferred_lft forever
```

The key thing to remember: **the Host address and the WSL address found above are dynamic IP addresses that can change at any time.**{:.orange}

To test the connection, install the required package and try connecting to MariaDB using the Host address we found, `172.25.16.1`.

<div class="file-name">Ubuntu</div>

```bash
$ sudo apt install mariadb-client-core-10.6
```

```bash
$ mariadb -h {host_ip} -P 3306 -u {your_username} -p

$ mariadb -h 172.25.16.1 -P 3306 -u root -p
```

If you get the error message below, grant the user access from that IP in MariaDB and you'll be able to connect. You can do this with `'username'@'WSL_ip'` in the command below. `FLUSH PRIVILEGES;` applies changes to user accounts or privileges immediately.

Since this is a development environment, we'll grant access from all IPs so it doesn't matter if the WSL IP changes. Running the command with `'username'@'%'` grants access from every IP.

```text
ERROR 1045 (28000): Access denied for user 'root'@'172.25.18.88' (using password: YES)
```

<div class="file-name">MariaDB</div>

```sql
GRANT ALL PRIVILEGES ON *.* TO 'user_id'@'WSL_ip or %' IDENTIFIED BY 'your_password';

GRANT ALL PRIVILEGES ON *.* TO 'root'@'%' IDENTIFIED BY '1234qwer!';

FLUSH PRIVILEGES;
```

## Automatically Writing the Host Address into .env

We've now confirmed that WSL can reach the Host's MariaDB. So we can just connect with VS Code and start developing, right? I created a folder called `/home/ubuntu/flask-app` and wrote the Host MariaDB details into a `.env` file.

<div class="file-name">.env</div>

```text
DB_ENGINE=mariadb+pymysql
DB_USER=root
DB_PASSWORD=1234qwer!
DB_HOST=172.25.16.1
DB_PORT=3306
DB_NAME=test
```

But here the Host's dynamic IP becomes a problem: every time the Host address changes, you have to update the connection details by hand. To fix that annoyance, let's have the `.env` file updated automatically every time WSL starts.

The `/etc/wsl.conf` file configures what happens each time WSL starts. We'll add a `command` option to the `[boot]` section.

<div class="file-name">Ubuntu</div>

```bash
$ sudo vim /etc/wsl.conf
```

<div class="file-name">wsl.conf</div>

```text
[boot]
systemd=true

command = env_path=/home/ubuntu/flask-app/.env; \
        ip_address=$(ip route show | grep -i 'default' | awk '{ print $3}'); \
        sed -i "s/^DB_HOST=.*/DB_HOST=$ip_address/" $env_pat
```

Now every time WSL reboots, it runs that `command` and updates the Host IP address. Try shutting WSL down with the command below and starting it again.

<div class="file-name">PowerShell</div>

```bash
> wsl --terminate {NAME}

> wsl --terminate Ubuntu
```

## Writing the flask-app

Now write some simple Flask code and check that it fetches data correctly at `localhost:5000`. Run it with `F5` debugging in VS Code to check.

<div class="file-name">app.py</div>

```python
from flask import Flask
from sqlalchemy.sql import text
from sqlalchemy.orm import Session
from sqlalchemy import make_engine

import os
from dotenv import load_dotenv

load_dotenv()

app = Flask(__name__)

DB_ENGINE = os.getenv("DB_ENGINE")
DB_USER = os.getenv("DB_USER")
DB_PASSWORD = os.getenv("DB_PASSWORD")
DB_HOST = os.getenv("DB_HOST")
DB_PORT = os.getenv("DB_PORT")
DB_NAME = os.getenv("DB_NAME")

engine = make_engine(
    url=f"{DB_ENGINE}://{DB_USER}:{DB_PASSWORD}@{DB_HOST}/{DB_NAME}"
)

@app.route("/")
def test_query():
    with Session(engine) as session:
        return session.execute(text("SELECT 'Hello WSL!'")).scalar_one()
if __name__ == "__main__":
    app.run(debug=True)
```

## Wrapping Up

**We used WSL (Windows Subsystem for Linux) on Windows to build a development environment close to the deployment environment.**{:.orange}

To go further, try setting things up to match your actual deployment environment, for example with `Nginx`, and develop against that. That way you'll be ready to deal with the problems that can come up when you actually deploy! 😊
