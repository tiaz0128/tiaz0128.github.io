## Implementing Multilingual Notification Messages

Here's the feature I actually built at work using **Server-Sent Events (SSE)** for notifications:

1. Periodically query the DB and send a notification if there's new data since the previous query time
2. On top of that, send the notification message **in the language the client selected**

## Overall Flow and Setup

The user can **change the language at any time** in the client UI. The client requests an SSE connection for the selected language, and each time it passes that language in the `Accept-Language` request HEADER.

The DB uses `id` and `lang` as the primary key, and the same `id` holds a notification message for each key such as `ko`, `en-US` and `jp`.

| id* | lang* | message | isn_dt |
| --- | --- | --- | --- |
| 5b48ff24 | ko | 예약에 성공했습니다! | 2023-12-01 11:10:04 |
| 5b48ff24 | US-en | I have successfully made a reservation. | 2023-12-01 11:10:04 |
| 5b48ff24 | ja | 予約に成功しました | 2023-12-01 11:10:04 |

## Server Implementation

Just query the DB using the `lang` value the client sends with its SSE request. In Flask, you can easily get this **from the `best` property** of `accept_languages` on the `request` object.

Pass the language received on the SSE connection as an argument to the generator function, use it to query the DB, and the user gets notifications in the language they selected.

<div class="file-name">app.py</div>
```python
from flask import request
from sse import get_user_alarm_by_lang

@app.get("/connection/<user_id>")
def connection(user_id: str):
    lang = request.accept_languages.best

    return Response(
        get_user_alarm_by_lang(user_id, lang), content_type="text/event-stream"
    )
```

<div class="file-name">sse.py</div>
```python
from time import sleep
import json

def select_alarm(user_id, lang):
    # DB query logic
    return { "message": "Your reservation was successful!" }

def get_user_alarm_by_lang(user_id, lang):
    PENDING_TIME = 5

    while True:
        data = select_alarm(user_id, lang)
        yield f"""event: alarm\ndata: {json.dumps(data)}\n\n"""
        sleep(PENDING_TIME)
```

## What If the User Changes the Language?

Suppose the user **changes the language** in the UI after already making an SSE request. The generator started with the previous language is no longer needed, so it has to be stopped. Then a new generator is started with the new language as the `lang` parameter.

1. The client **requests an SSE connection again** with the selected language
2. If a previous connection exists, it is closed
3. Only the new connection remains, and notifications are delivered through it

## The Problem with SSE

**The catch, though,** is that SSE is **one-way communication**: only the server can talk to the client. The server can send data to the client, but responses or status checks from the client aren't provided out of the box. Of course, the basic connection error detection lets you close a connection. But when SSE connections are legitimately requested several times, **there's no way to detect** **duplicate connections**, so something extra is needed.

## Implementing Connection Management

Connection management can be **implemented simply with a global variable**. First, create a global `dict` to track connections. Then write logic that **keeps the global variable updated with a random value from the latest request and compares against it**.

1. Generate a random value for each SSE request
2. Overwrite the connection-tracking global variable with that value
3. Pass each request's random value when calling the generator
4. Inside the generator, **compare the value it received with the connection-tracking global variable**
5. If it isn't the latest connection, `break` out of the generator to end the connection

<div class="file-name">app.py</div>
```python
from flask import request
from sse import get_user_alarm_by_lang, client_connections
from uuid import uuid4

@app.get("/connection/<user_id>")
def connection(user_id: str):
    current_conn_id = uuid4().hex
    client_connections[user_id] = current_conn_id # overwrite with the latest value

    lang = request.accept_languages.best

    return Response(
        get_user_alarm_by_lang(user_id, lang, current_conn_id), 
        content_type="text/event-stream"
    )
```

<div class="file-name">sse.py</div>
```python
from time import sleep
import json

client_connections = {}

def get_user_alarm_by_lang(user_id, lang, current_conn_id):
    PENDING_TIME = 5

    while True:
        # compare the global variable's latest value with the value passed in on the call
        if client_connections.get(user_id) != current_conn_id:
            print(f"BYE BYE conn_id:{current_conn_id}")
            break

        data = select_alarm_by_lang(user_id, lang)
        yield f"""event: alarm\ndata: {json.dumps(data)}\n\n"""

        sleep(PENDING_TIME)
```

## Client Implementation

By default, SSE reconnects automatically when the connection drops on the client, so the client also **needs a proper implementation** to handle the server closing the connection.

<div class="file-name">js</div>
```jsx
const eventSource = new EventSource('http://localhost:5000/connection/tiaz');

eventSource.onerror = function() {
    eventSource.close()
    // You can implement reconnection logic here if needed.
};
```

## Concurrency Issues

There's one more thing to think about. Flask itself is a web framework that supports **multithreading**. That can lead to concurrency problems such as **race conditions and deadlocks**. To prevent them, you need a proper synchronization mechanism. Here we'll use a **thread lock**.

<div class="file-name">app.py</div>
```python
from threading import Lock

connections_lock = Lock()

@app.get("/connection/<user_id>")
def connection(user_id: str):
    current_conn_id = uuid4().hex

    with connections_lock:
        client_connections[user_id] = current_conn_id

    lang = request.accept_languages.best

    return Response(
        get_user_alarm_by_lang(user_id, lang, current_conn_id),
        content_type="text/event-stream",
    )
```

## Epilogue: More to Think About

Flask also supports multiprocessing. If the environment running your Flask application is multi-process, each process has **its own memory space**. So **the global variable implemented above is not shared between processes.**

Using a global variable also means the server **keeps state**, which can undermine the server's stateless nature. That can **affect scalability and maintainability**.

So in such environments, it should be improved to share the data through an external data store such as **Redis**. 😊
