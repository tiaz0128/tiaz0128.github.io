## MCP (_Model Context Protocol_)

The Model Context Protocol (MCP) is a protocol that provides context in a standardized way so that large language models (LLMs) can interact with applications.

You could say it's a way to let an LLM use the various applications I use as tools. Like an assistant who knows me well and helps with my work, it lets the LLM grow into an agent.

### Key Components of MCP

- Host : an LLM-based application (e.g. Claude Desktop, Cursor, Docker AI...)
- Client : maintains a 1:1 connection with a server
- **Server**{:.orange} : provides specific capabilities or resources

## MCP Server Components

- **Tools**{:.orange} : give the LLM functions to perform actions (including side effects) (similar to a POST endpoint)
- Prompts : templated messages for interacting with the LLM
- Resources : provide read-only data to the LLM (similar to a GET endpoint)

## MCP Server Code

{% include template/alert.html
  type="tip"
  about="In this example, we'll use `tool` and `prompt`."
%}

`attendance-A.md`{:.path} and `attendance-B.md`{:.path} each hold a list of attendees. The `seminar_attendees` function reads those files and returns the attendees as a list.

<div class="file-name">src/server.py</div>

```python
from mcp.server.fastmcp import FastMCP
from seminar import seminar_attendees
from datetime import datetime
import json

mcp = FastMCP("Seminar Management System")

@mcp.tool()
def get_seminar_details(party_name: str) -> str:
    attendees = seminar_attendees(party_name)

    seminar_info = {
        "name": party_name,
        "total_attendees": len(attendees),
        "attendees": attendees,
    }

    return json.dumps(seminar_info, ensure_ascii=False, indent=2)

@mcp.tool()
def register_attendee(party_name: str, attendee_name: str) -> str:
    # A real implementation would add the attendee to the file here

    return f"Success: {attendee_name} has been registered for the {party_name} seminar."

@mcp.prompt()
def prompt(message: str) -> str:
    return f"""
You are the AI assistant of a seminar management system.

Available tools:
- get_seminar_details(party_name) - Look up the details of a specific seminar.
- register_attendee(party_name, attendee_name) - Register a new attendee.

User message: {message}
"""

if __name__ == "__main__":
    mcp.run()
```

### Tool

- Registered as a function the LLM can execute
- `@mcp.tool()`

### Prompt

- A template for interacting with the LLM
- Takes the input message and provides reusable instructions to pass to the LLM
- `@mcp.prompt()`

## Debugging and Running the MCP Server

### Using MCP Inspector

MCP Inspector is the best way to test and debug a server. The command below runs the MCP server in development mode and opens the Inspector interface, where you can test resources, tools and prompts.

```bash
$ mcp dev src/server.py

Starting MCP inspector...
Proxy server listening on port 3000

🔍 MCP Inspector is up and running at http://localhost:5173 🚀
```

### Debugging Tip

When you connect an MCP server to Claude Desktop, you can check its logs in the `logs` folder under the folder that holds `claude_desktop_config.json`.

### Dockerfile

The easiest way I found to connect the MCP server I built to MCP clients, regardless of environment, was to use Docker.

<div class="file-name">Dockerfile</div>

```docker
FROM python:3.11-slim

WORKDIR /app

# Install curl
RUN apt-get update && apt-get install -y curl

# Copy the whole project
COPY . .

# Install uv (goes into the global install location)
RUN curl -LsSf https://astral.sh/uv/install.sh | sh

# Add the uv install path to PATH
ENV PATH="/root/.local/bin:${PATH}"

# Create a virtual environment and install the project
RUN uv venv .venv && uv pip install -r pyproject.toml

# Open the required ports
EXPOSE 3000
EXPOSE 5173

# Run the MCP server
ENTRYPOINT ["uv", "run", "mcp", "run", "src/server.py:mcp"]
```
