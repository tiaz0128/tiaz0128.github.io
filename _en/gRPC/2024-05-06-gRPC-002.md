## RPC (Remote Procedure Call)

`RPC` is a protocol, based on the client-server model, that lets you call a remote procedure as if it were a local one. Regardless of language, the server and client can communicate based on the same interface.

### How It Works

1. The client calls a function locally
2. The RPC system serializes the call and sends it over the network
3. The server receives the request, deserializes it and runs the function
4. The result is serialized again and sent back to the client
5. The client receives the result, deserializes it and uses it

![gRPC](/assets/img/content/gRPC/002/001.webp){:.img-m}

## gRPC (gRPC Remote Procedure Calls)

`gRPC` is an open-source RPC framework developed by Google that uses protobuf as its implementation.

![gRPC](/assets/img/title/gRPC/gRPC.webp){:.img-200x200}

### Key Features

- Uses protobuf as its `IDL (Interface Definition Language)`
- Communication over HTTP/2
- Supports many programming languages

### How It Works

- Define the service with protobuf
- Generate server and client code from the service definition (service)
- Client and server communicate using the generated code

## Writing the .proto Files

First, we'll write the `.proto` protobuf files as the `IDL (Interface Definition Language)` shared by the server and client. We'll create two files under the _protos_ folder.

```text
project/
└── protos/
    └── person.proto
    └── route_guide.proto
```

### person.proto

Defines the `message` that represents our data.

<div class="file-name">protos/person.proto</div>

```text
syntax = "proto3";

message Person {
    string name = 1;
    int32 age = 2;
    enum Gender {
        UNKNOWN = 0;
        MALE = 1;
        FEMALE = 2;
    }
    Gender gender = 3;
    repeated string hobbies = 4;
    
    message Address {
        string street = 1;
        string city = 2;
    }
    Address address = 5;
}
```

### route_guide.proto

Defines the gRPC `service` that describes the server and client. This service contains two RPC methods.

<div class="file-name">protos/route_guide.proto</div>

```text
syntax = "proto3";

import "person.proto";

message Name {
  string name = 1;
}

service RouteGuide {
    rpc GetPerson(Name) returns (Person) {}
    rpc GetPeople(stream Name) returns (stream Person) {}
}
```

### GetPerson

```text
rpc GetPerson(Name) returns (Person) {}
```

- The client sends a single Name message to the server, and the server responds with a single Person message

### GetPeople

```text
rpc GetPeople(stream Name) returns (stream Person) {}
```

- The client sends a stream of Name messages to the server
- The server responds with a stream of Person messages
- Lets you look up several people at once, or keep requesting and receiving people's information in real time

```text

```

## The Compiled Output Files

### `*_pb2.py` Files

These define the protobuf messages. You use them to define and manipulate data structures.

- A Python class for every message type defined in the .proto file
- Getter and setter methods for each field
- Serialization and deserialization methods

### `*_pb2_grpc.py` Files

These define the gRPC service. You use them to implement the gRPC server and to call the service from the client.

- Server side: a Servicer class for implementing the service
- Client side: a Stub class for calling the service
- A function for registering the service with a gRPC server

### `*_pb2.pyi` Files

These provide type hinting information. They support type checking in IDEs and type checkers like mypy, and improve code completion and documentation.

- Type information for the classes and functions defined in *_pb2.py
- Message field types, method parameters and return types, etc.

With these three files, developers can work with protobuf messages and implement gRPC services efficiently while keeping type safety. The *_pb2.pyi file is optional, but very useful in large projects or where type safety matters.

### Full sever.py Code

<div class="file-name">src/server.py</div>

```python
import grpc
from concurrent import futures
import person_pb2
import route_guide_pb2_grpc
class RouteGuideServicer(route_guide_pb2_grpc.RouteGuideServicer):
    def __init__(self):
        self.people = {
            "Alice": person_pb2.Person(
                name="Alice",
                age=30,
                gender=person_pb2.Person.FEMALE,
                hobbies=["reading", "swimming"],
                address=person_pb2.Person.Address(
                    street="123 Main St", city="New York"
                ),
            ),
            "Bob": person_pb2.Person(
                name="Bob",
                age=25,
                gender=person_pb2.Person.MALE,
                hobbies=["gaming", "cycling"],
                address=person_pb2.Person.Address(
                    street="456 Elm St", city="Los Angeles"
                ),
            ),
        }

    def GetPerson(self, request, context):
        name = request.name
        return self.people.get(name, person_pb2.Person(name="Not Found"))

    def GetPeople(self, request_iterator, context):
        for name_request in request_iterator:
            person = self.people.get(name_request.name)
            if person:
                yield person

def serve():
    server = grpc.server(futures.ThreadPoolExecutor(max_workers=10))
    route_guide_pb2_grpc.add_RouteGuideServicer_to_server(RouteGuideServicer(), server)
    server.add_insecure_port("[::]:50051")
    print("Server started on port 50051")
    server.start()
    server.wait_for_termination()

if __name__ == "__main__":
    serve()
```

### Importing the Required Modules

We import the gRPC library and concurrent.futures, along with the person_pb2 and route_guide_pb2_grpc modules generated from the protocol buffers.

```python
import grpc
from concurrent import futures
import person_pb2
import route_guide_pb2_grpc
```

### The RouteGuideServicer Class

 The init method creates sample data. The class inherits from `route_guide_pb2_grpc.RouteGuideServicer` and implements the service logic.

- _GetPerson_ : a single request-response pattern. Used to request one person's information
- _GetPeople_ : a streaming request-response pattern. Used to request several people's information

```python
class RouteGuideServicer(route_guide_pb2_grpc.RouteGuideServicer):
    def __init__(self):
        self.people = {
            "Alice": person_pb2.Person(...),
            "Bob": person_pb2.Person(...),
        }

    def GetPerson(self, request, context):
        name = request.name
        return self.people.get(name, person_pb2.Person(name="Not Found"))

    def GetPeople(self, request_iterator, context):
        for name_request in request_iterator:
            person = self.people.get(name_request.name)
            if person:
                yield person
```

### The serve Function

Sets up and starts the gRPC server. It uses a ThreadPoolExecutor to handle concurrent requests with up to 10 workers.
It binds the server to port 50051 and starts it.

```python
def serve():
    server = grpc.server(futures.ThreadPoolExecutor(max_workers=10))
    route_guide_pb2_grpc.add_RouteGuideServicer_to_server(RouteGuideServicer(), server)
    server.add_insecure_port("[::]:50051")
    print("Server started on port 50051")
    server.start()
    server.wait_for_termination()
```

### Full client.py Code

<div class="file-name">src/client.py</div>

```python
import grpc
import route_guide_pb2
import route_guide_pb2_grpc

def run():
    with grpc.insecure_channel('localhost:50051') as channel:
        stub = route_guide_pb2_grpc.RouteGuideStub(channel)

        # Call GetPerson
        name = route_guide_pb2.Name(name="Alice")
        person = stub.GetPerson(name)
        print(f"GetPerson: {person.name}, Age: {person.age}, Gender: {person.gender}, "
              f"Hobbies: {person.hobbies}, Address: {person.address.street}, {person.address.city}")

        # Call GetPeople
        names = [route_guide_pb2.Name(name="Alice"), route_guide_pb2.Name(name="Bob"), route_guide_pb2.Name(name="Charlie")]
        people = stub.GetPeople(iter(names))
        for person in people:
            print(f"GetPeople: {person.name}, Age: {person.age}, Gender: {person.gender}, "
                  f"Hobbies: {person.hobbies}, Address: {person.address.street}, {person.address.city}")

if __name__ == '__main__':
    run()
```

### Importing the Required Modules

We import the grpc library and the route_guide_pb2 and route_guide_pb2_grpc modules generated from the protocol buffers.


### Creating a gRPC Channel

Create a channel that connects to the server.

```python
with grpc.insecure_channel('localhost:50051') as channel:
```

### Creating a Stub

Create a stub that can call the server's service. With this stub, you can talk to the server without any complicated implementation.

```python
stub = route_guide_pb2_grpc.RouteGuideStub(channel)
```

### Calling the GetPerson RPC

Call GetPerson and print the information from the returned Person object.

```python
name = route_guide_pb2.Name(name="Alice")
person = stub.GetPerson(name)
print(f"GetPerson: {person.name}, ...")
```

### Calling the GetPeople RPC

Call GetPeople with a list of names as a stream. The response also comes back as a stream. Print the information from each Person object.

```python
names = [route_guide_pb2.Name(name="Alice"), ...]
people = stub.GetPeople(iter(names))
for person in people:
    print(f"GetPeople: {person.name}, ...")
```

## Wrapping Up

gRPC uses protobuf as its IDL (*Interface Definition Language*) to define `message`s and `service`s. You implement the client and server using the compiled sources.

With a `Stub`, you can call procedures between client and server *(RPC = Remote Procedure Call)*. The data exchanged is in protobuf format.

![gRPC](/assets/img/content/gRPC/002/002.webp)

Here we compiled both client and server to Python, but you can compile the same `.proto` file to different languages and call it the same way.

If you're building services with a microservices architecture (MSA), implementing server-to-server communication with gRPC could be a great option. 😊
