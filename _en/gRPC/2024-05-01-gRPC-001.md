Let's take a look at `Protocol Buffers`, which gRPC uses.

## Protocol Buffers

`Protocol Buffers` is a binary serialization format created by Google, often shortened to `protobuf`. Like JSON, YAML and XML, it's a format for representing data.  The biggest difference from those familiar formats is that it represents data in binary. Here are the pros and cons of `protobuf`.

### Pros

- Very fast serialization and deserialization
- Small data size, so network transfer is efficient
- Usable from many programming languages (Java, Python, C++, Go, etc.)
- Type checking at compile time helps prevent runtime errors

### Cons

- Being binary, it's hard for humans to read and hard to debug
- You have to learn how to write .proto files and how to use protobuf
- Hard to use directly in a web browser
- For simple data exchange, it's overly complex compared to JSON or XML

## Writing a .proto File

The very first step is to write a schema file called `.proto`. Compiling this file produces files that let each language use `protobuf`. Think of it as generating interface code.

Let's write one while comparing a basic JSON data structure with its `.proto` equivalent.

### JSON

```json
{
    "person": {
        "name": "tiaz0128"
    }
}
```

### Writing the .proto

We'll write a file called `person.proto` under the protos folder.

`syntax = "proto3"` means we're using version 3, which is what's mostly used. If you leave out the syntax statement, version 2 is used by default, so always include it.

<div class="file-name">protos/person.proto</div>

```text
syntax = "proto3";

message Person {
  string name = 1;
}

message Data {
  Person person = 1;
}
```

## Writing Messages

A `message` is the core building block of protobuf and is used to define data structures. Let's go over the basic syntax.

### Code

<div class="file-name">protos/person.proto</div>

```text
syntax = "proto3";

message Person {
    string name = 1;
    int32 age = 2;
    enum Gender {
        UNKNOWN = 0;
        MALE = 1;
        FEMALE = 2;
    }
    Gender gender = 3;
    repeated string hobbies = 4;
    
    message Address {
        string street = 1;
        string city = 2;
    }
    Address address = 5;
}
```

### Basic Structure

```text
string name = 1;
```

- Fields are defined inside curly braces `{}`
- Starts with the message keyword, followed by the message name
- Each field is defined in the form `type name = number;`
- Each field is assigned a unique number (range 1-536,870,911).
- Numbers 1-15 take only one byte when encoded, so they're recommended for frequently used fields

### Data Types

```text
repeated string hobbies = 4;

message Address {
    string street = 1;
    string city = 2;
}
Address address = 5;
```

- string, integers (int32, int64), floating point (float, double), boolean (bool), etc.
- Enum definitions : you can define an enum inside a message
- Repeated fields : use the repeated keyword to define repeated fields such as arrays or lists
- Nested messages : you can define a message inside another message

### Field Options

- `optional` : in proto3, all fields are treated as optional by default
- `required` : used in proto2. Not used in proto3

### Comments

- `//` : single-line comment
- `/* */` : multi-line comment

## Compiling the .proto

### The src Folder

Create a `src` folder and run the compile command below from there.

```text
project/
├── protos/
│   └── person.proto
└── src/
    └── (you are here)
```

### protoc

Use `protoc` to compile the `.proto` file into Python code.

```bash
$ python -m grpc_tools.protoc -I../protos --python_out=. ../protos/person.proto
```

- `I../protos` : specifies the directory to look for proto files in
- `-python_out=.` : writes the generated Python code to the current directory
- `../protos/person.proto` : specifies the path of the proto file to compile

### Output File

The output file is named after the original .proto file with `_pb2` appended. From person.proto, a file called person_pb2.py is generated.

```text
project/
├── protos/
│   └── person.proto
└── src/
    └── *person_pb2.py (output file)
```

### _pb2.py

The generated code includes the following.

- Message class definitions
- Field definitions and metadata
- Enum definitions
- Serialization/deserialization methods
- Descriptor information

## Serialization

Let's add a `main.py` file and see how to serialize a message into binary format using the compiled file.

```text
project/
├── protos/
│   └── person.proto
└── src/
    └── person_pb2.py
    └── *main.py (new file)
```

### Code

- The `Person` class corresponds to the Person message defined in person.proto.
- We assign a value to the name field of the protobuf object.
- `SerializeToString` serializes the message into binary format. The result is a byte string.

<div class="file-name">src/main.py</div>

```python
import person_pb2

person = person_pb2.Person()
person.name = "tiaz0128"

serialized = person.SerializeToString()
print(isinstance(serialized, bytes))
```

Serialized data in binary format is very efficient, and well suited to network transfer or saving to files.

## Deserialization

Now let's see how to deserialize the binary data back into a protobuf object.

### Code

Create a new protobuf object and deserialize with the `ParseFromString` method.

```python
new_person = person_pb2.Person()
new_person.ParseFromString(serialized)

print(new_person.name)
```

It parses the byte string and assigns each field's value to the matching field of the object, interpreting the data according to protobuf's encoding rules.

If malformed data comes in, an exception is raised; if incomplete data comes in, it still tries to parse as much as it can.
Only the parsed fields are set, and the rest keep their default values.

## Serializing to Other Formats

You can serialize to other formats such as JSON or dictionaries and deserialize back into a `protobuf` object. You can also save to files or work with streams.

### JSON Format

```python
from google.protobuf.json_format import MessageToJson, Parse

json_string = MessageToJson(person)
other_person = person_pb2.Person()
Parse(json_string, other_person)
```

### Dictionary Format

```python
from google.protobuf.json_format import MessageToDict, ParseDict

dict_data = MessageToDict(person)
other_person = person_pb2.Person()
ParseDict(dict_data, other_person)
```

## Wrapping Up

`Protocol Buffers` is a format for representing data, like JSON or XML. Unlike those text-based formats, it uses binary data.

- Small and fast, but hard to read or debug
- Write a schema file → `.proto`
- Use the compiled output in your implementation → `_pb2`
- Serialize → `SerializeToString`
- Deserialize → `ParseFromString`
- Supports serializing and deserializing to other formats
