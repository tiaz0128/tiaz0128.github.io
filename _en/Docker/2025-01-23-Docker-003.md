## Advantages of Containers

What do you gain by using container virtualization? Let's think it through by imagining installing several Python versions on a physical machine versus in containers.

### Setting Up on a Physical Machine

Have you ever installed several versions of the same programming language on one computer? Most of the time something doesn't work right, probably because they interfere with each other.

![Docker Engine](/assets/img/content/Docker/003/001.webp){:.img-m}

`> Version conflicts on a single physical machine`{:.img-caption}

### Setting Up with Containers

What if you build the environment with containers instead? A container gives you an isolated runtime with exactly the setup you need. The advantage is that it runs independently of the host system and other containers.

![Docker Engine](/assets/img/content/Docker/003/002.webp){:.img-m}

`> Building independent environments with containers`{:.img-caption}

## Docker Engine

The Docker Engine acts as a `client` - `server application` that manages and runs containers. It is made up of three components.

- Docker daemon(_dockerd_)
- Docker CLI(_command line interface_)
- Docker APIs

![Docker Engine](/assets/img/content/Docker/003/003.webp){:.img-m}

`> The Docker Engine is made up of three components.`{:.img-caption}

### Docker daemon(dockerd)

The Docker Daemon listens for Docker API requests and manages Docker objects such as images, containers, networks and volumes.

### Docker CLI

The Docker CLI is the set of docker commands users run, and it uses the Docker APIs. You control or interact with the Docker daemon through scripts or by running CLI commands directly.

### Docker APIs

The APIs that programs use to talk to and instruct the Docker daemon.

## Image

Containers are created from images. An image is a read-only template for creating containers, and a single image can run many containers.

## Docker Hub

Docker Hub is a repository that collects many images. Images that don't exist locally can be pulled from Docker Hub.

## Docker CLI Command Structure

The basic structure of a Docker CLI command is:

```bash
$ docker target COMMAND [OPTIONS] [ARG...]

$ docker container run -it python
```

Uppercase parts (e.g. COMMAND) are required. Square brackets `[ ]`{:.path} mark options, and the `...`{:.path} after ARG means one or more values. Finally, the common targets are:

- image
- container
- volume
- network

### The New Command Format

The two commands below both 'run a container'. The difference is whether a target such as `container` is present. The form with a target followed by a subcommand is the new command format.

```bash
$ docker run

$ docker container run
```

Which format looks clearer to you? I **recommend the new command format, where the target is explicit.**{:.orange}

### --help

While using the CLI, you can look up the commands or options you need with the `--help` option, as below. It gives you the information you need for the command at each level.

```bash
$ docker --help

$ docker container --help

$ docker container run --help
```

## Running the hello-world Container

Now let's run the simple `hello-world` container. Run the command below.

```bash
$ docker container run hello-world
```

```bash
Hello from Docker!
This message shows that your installation appears to be working correctly.

(omitted)
```

### How the hello-world Container Runs

1. Looks for the `hello-word` image locally (it isn't there)
2. Finds the `hello-word` image on Docker Hub and pulls it
3. Creates a container from the image and runs it
4. The container runs and exits

![Docker Engine](/assets/img/content/Docker/003/006.webp)

`> The hello-word container exits right after it runs`{:.img-caption}

### Checking the Container State

The `hello-world` container exits as soon as it has done its job. The command below shows that the container is in the `Exited` state.

```bash
$ docker container ls --all
```

```bash
CONTAINER ID   IMAGE            COMMAND     CREATED         STATUS
6cf19ed48d78   hello-world      "/hello"    29 minutes ago  Exited (0) 29 minutes ago
```

## Wrapping Up

Let's wrap up with a recap of containers, the Docker Engine and images. In the next post, we'll take a closer look at **'container commands and container states'**{:.orange}! 😊

### Containers

Containers let you package an application and its runtime environment in isolation. That way you can run multiple applications without version conflicts or environment configuration problems.

### Docker Engine

The Docker Engine is the core component that manages these containers.

- The Docker daemon acts as the server that manages containers and images
- Users interact with the Docker daemon through the Docker CLI
- The Docker API provides the interface programs use to talk to the Docker daemon

### Images

You need an image to start a container, and images can be pulled from Docker Hub or built yourself.
